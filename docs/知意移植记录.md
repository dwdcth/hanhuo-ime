## 关键工程决策

1. **clean-room**：规格源=官方 README+test_vectors（Apache-2.0）；
   包内 GPL 参考码物理移除, 不读不抄
2. **手写 BPE 保持**（kitoken 评估后不换）：已逐位对拍、零依赖、
   非瓶颈（前向 ~60ms 主导）
3. **呈现层重排**：只排名次不写回 Cand.score（跨读法门槛零污染）
4. 开发线归 release（Apache-2.0 资产; 曾误入研究仓已 revert 迁出）

## root cause 战例（rope 单头 bug）

电池 0.8% → numpy 复刻**逐位对官方**（证明规格理解全对）→ rust
emb 一致 → 层0 分叉 → attn 内 q 一致 k 错 → rope 对已 narrow 的
单头张量仍按多头布局切（hd=64/6=10 错位; q 行0 恰在旋转角零点
掩盖）。教训：**多维 reshape 后的 rope 必须按张量实际维数算**,
逐层中间量对拍是定位这类 bug 的最快路径。

## 长句瓶颈的最终裁定（三轮实证）

1. zh.ngram 三元插值：+0.3pp（噪声级）
2. 词路径保位（WORD_BONUS 钮 0-2）：无效
3. 知意重排（54 长句 ctx）：0——gold 在池 13%

**全部指向召回侧**：正确句不在候选池, 任何重排件无效。长句正解
= P2C 生成（拼音→汉字直接解码, 不依赖词图 beam）——与青简
51.9% vs 42.3% 的实证一致。知意的词级语境增益（+9.3pp）已兑现,
composition 头（逐音节出字进词图）是另一个待评估的召回侧武器。

## wasm 侧体积裁定（2026-11-14, Q8_0 实测）

| 件 | 体积 | 裁定 |
|---|---|---|
| 知意 Q8_0（线性 32MB + **embedding 94MB 保不下** + tokenizer 34MB）| **~160MB** | **wasm 排除**（demo 全站才 90MB; embedding 不可量化——README 明令）|
| P2C 自训（8×d384, vocab 8k 小嵌入）Q8_0 估 | **~10-15MB** | **wasm 可行**——自训线战略价值再加一层 |

大词表 BPE（112k token）嵌入是知意 wasm 死穴; 自训 P2C 用 8k 汉字表
天然规避。wasm 侧神经增强 = 自训 P2C 线。

## P2C 战役阶段报告（2026-11-14, v1 评负 + v2 混训中）

| 阶段 | 结果 |
|---|---|

门槛律, 或 P2C 候选按分数带注入不钉死）。
