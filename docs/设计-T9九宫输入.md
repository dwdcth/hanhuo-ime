## 1. 问题域与现状

**目标**: 九宫键盘（2=abc … 9=wxyz）数字键串 → 中文候选。微信移动端
T9 是完整产品线（会话类型五型实证含 T9——（参考自逆向研究档案）;
PC 版不用——（参考自逆向研究档案））, hanhuo 目前**零通道**:
（逆向研究档案确认 T9 纠错件未被开源链引用）,
词库台账将其挂「待 T9 战役（方向池）」（词库台账-微信全词库与开源替代.md:64）。

**现状三道门（T9 键串今天进不了管线）**:

1. **数字阻断律**: 白名单外任何字符整链空返回, 白名单 = 字母+撇号+空格
   +数字 1-5（query.rs:809-814）。九宫键串含 6-9, 直接空面板。
2. **调号征用冲突**: 数字 1-5 已被声调筛选征用为调约束（query.rs:816-818,
   `strip_tones`——mod.rs:199）。九宫的 2-5 是字母域键, 语义二义
   ——T9 模式必须先于该门分叉。
3. **无九宫展开源**: 现有展开通道全是字母域——简拼 `q_jianpin` 的
   `jianpin_keys` 查 `jian_keys` 二分表（channels_full.rs:9-78）,
   键是字母串; 九宫键串需要「数字→音节集合」的新展开律。

**可复用的既有资产**（本设计的支点）:

| 件 | 位置 | T9 复用点 |
|---|---|---|
| DAT 读音索引（56.4 万键/190 万槽, 键=无分隔连写拼音） | README.md:110; q_jianpin 消费口 channels_full.rs:2705-2742 | 展开产物直接喂 `dat.walk`+`range_candidates` |
| `jianpin_dat_compose`: DFS + DAT 前缀剪枝 + 50,000 walk 步预算, cap 48 | channels_full.rs:729-767 | **架构 c 的直接模板**——首字母栈换数字签名栈 |

## 2. 键位映射与组合爆炸分析

### 2.1 键位映射

标准九宫（与微信引擎 a-z→2-9 硬编码映射 0x1807de680 同构——
（见研究档案））:

| 键 | 字母 | 键 | 字母 |
|---|---|---|---|
| 2 | abc | 6 | mno |
| 3 | def | 7 | pqrs |
| 4 | ghi | 8 | tuv |
| 5 | jkl | 9 | wxyz |

音节→键串 = 逐字母映射（如 zhuang→948264, ni→64, qing→7464）。

### 2.2 组合爆炸: 三级口径（实测）

用 pypinyin 单字读音表 NFD 归一无调得 **421 音节**（与 bccn 409 音节空间
同族——（见研究档案）; 引擎两档 409/416, 差异为罕音节/俚语音节,
不影响量级）, 得 **225 个相异数字签名**（音节级去重 46%: pi/qi/ri/si→74）,
签名最长 6（zhuang/chuang）。三级计数:

| 口径 | 含义 | 计数律 |
|---|---|---|
| L1 字母级 | 逐键字母笛卡尔积 | 3ⁿ..4ⁿ（**错误做法的口径**） |
| L2 音节级分解 | 键串切成合法音节序列的方式数（含多 segmentation） | 有限状态 DP, 实测见下表 |
| L3 去重拼音串 | 分解去重后的相异拼音串 | L2 的 0.1~1.0 倍 |

| 键串 | L2 分解 | L3 拼音串 | | 键串 | L2 分解 | L3 拼音串 |
|---|---|---|---|---|---|---|
| 64 (ni) | 3 | 3 | | 8 键 22222222 | 171 | 171 |
| 426 (hao) | 6 | 4 | | 8 键 99999999 | **0** | 0 |
| 7464 (4 键) | 14 | 12 | | 10 键 2264426426 | 936 | 270 |
| 64426 (nihao) | 18 | 12 | | 12 键 222222222222 | 2,731 | 2,731 |
| 8 键 64426363 | 138 | 66 | | 12 键 262626262626 | 22,312 | 2,131 |
| 8 键 94664486 (zhongguo) | 102 | 64 | | 12 键 999999999999 | **0** | 0 |

（参照: L1 字母级 8 键 = 6,561..65,536, 12 键 = 531,441..16,777,216）

**结论**:
1. **音节级枚举把爆炸压掉 2-3 个数量级**: 12 键最坏 2.2 万分解
   （vs 字母级 1,677 万）; 常规 4-8 键输入在 **10² 数量级**。
2. **纯辅音域自然归零**: 全 9 键（wxyz 域）分解数 = 0——音节合法性
   天然剪枝, 无需词典即可砍掉大量死枝（DFS 第 1-2 层即断）。
3. **L2→L3 去重**在元音富集键串（2/6 键多）上再收一个数量级
   （262626262626: 22,312→2,131）。
4. **词典剪枝（DAT walk 制导）是最后一层**: L2/L3 是无词典上界;
   沿 DAT 前缀态走查, 非词典前缀的枝在第 k 键即断——这正是
   `jianpin_dat_compose` 预算制的既有机制（channels_full.rs:760,
   50,000 walk 步上限）。

### 2.3 时延预算

<10ms 预算的构成（估算, P1 落地时 bench 定档）: 常规 8 键 ≤186 分解 →
DFS 走查 ≤ 数千 DAT 步（每步 O(1) 数组访问, ADR-002 附录17 kbest 热路径
优化后 156µs/千面 量级）+ 每命中 `range_candidates` top-k（heap 封顶
MAX_RANGE_HEAP=8192, constants.rs:605）。对照: 全链正确组均值 38ms
（评测-长句基线.md:53）中 jianpin 通道占微秒级; T9 走查同量级。
预算帽（同 50,000 步律）作硬上界保险。

## 3. 三个候选架构方案对比

### 方案 a: 键串→音节枚举→DAT 批查

先枚举全部合法拼音串（L3 口径, §2.2 表）, 再逐串 `dat.walk` +
`range_candidates`——即 `q_jianpin` 的形状换展开源
（channels_full.rs:2672-2744 的消费口原样复用）。
- 优点: 实现最薄（一个展开函数 + 既有消费口）; 展开序可控（sylw 权重序）。
- 缺点: 枚举与词典无关——死枝（非词典前缀）也要走完全程枚举再逐串查;
  12 键最坏 2,131 串 × walk+range, 无中途剪枝; 前缀/在途面板要靠
  「枚举所有再截前缀」间接获得。

### 方案 b: 离线九宫索引（键串→词预生成）

构建期把 738,028 词条（词库台账:15,118）每条读音映射成数字键串,
预生成「九宫键 DAT/哈希 → rid 列表」旁挂 section——即微信 ckvdmac 的
路线（九宫格按键串与全拼字母享有平等哈希桶检索权——
（见研究档案））, 也是 open bin `jian_*` section 的
同构扩展（词库台账 B 域 bwcjp_jianpin 行）。
- 优点: 查询 O(1); 与微信移动端架构对位最正; 键空间去重后估 ~30-40 万键
  （读音键 56.4 万 × 数字碰撞去重 ~35-45%, §2.2 音节级 46% 去重的词级外推）。
- 缺点: ① 新数据件——bin 格式、构建管线、双 bin（wxq/open）各一份;
  ② **组句不可能预生成**: 词级/句级组合（`jianpin_sent_beam` 形态的
  「闭词列×前缀态」搜索）键空间是乘积性的, 静态索引只覆盖整词键,
  句级仍要在线格 DP——届时 DP 走在字母 DAT 上还是九宫 DAT 上?
  前者回到方案 c, 后者要再造一条九宫 DAT 的 iter_terminal 族
  （dp_reachable 同构件, typo_retry.rs:378-390）; ③ fuzz/纠错通道
  （typo_retry 对变体串重查）全部只认字母域, 九宫索引服务不到。

### 方案 c: 键串→音节 trie 在线走查（DAT 制导 DFS）✅ 推荐

`jianpin_dat_compose` 的数字化泛化: 预计算音节表（409/416）每音节的
数字签名, 倒排为「签名→音节组」（225 桶, 启动期一次）; 查询期 DFS
状态 = (已消费键数, DAT 前缀态, 已积累音节 id 列), 转移 = 下一段
1..6 键查签名桶 × 逐音节 `dat.walk` 续走, 死态即剪枝, 预算帽 50,000
walk 步 + cap 同律。产物 `Vec<Vec<u32>>`（音节 id 序列）**与
`q_jianpin` 消费口逐字节同形**（channels_full.rs:2705-2742 原样复用:
拼 key → walk → range_candidates → Kind 标记）。
- 优点: ① **零新数据件**——DAT 已 mmap 在位, 双 bin 免改;
  ② 词典剪枝进枚举内部, §2.2 的 L2 上界再收一档; 预算帽 = 时延硬上界;
  ③ **在途面板免费**: DFS 沿途的 DAT 前缀态即补全面板（对应微信 sepd
  补全 trie 的角色——wetyp-B档终版交接-2026-10-22.md:115）; ④ 组句/
  fuzz/用户词/L4 打分全链复用（展开后就是普通拼音串候选）。
- 缺点: 每查询重复走查（无 O(1)）; 最坏输入靠预算帽截断有丢召回风险
  （§7-R4）; 展开优先级需要排序律（sylw 权重序, 同 jianpin_dat_compose
  的 `by_ini` 权重降序预处理——channels_full.rs:743-756）。

### 选型结论: **c**

一句话理由: 738k 词典规模下在线 DFS 的预算制走查（µs 级、上界硬帽、
零新数据件）完全够用, 而静态九宫索引买不到组句/纠错/补全任何一个
动态能力——微信走 b 是因为 ckvd 是 914 万短语无法在线 DFS
（（见研究档案））, 我们的规模差一个数量级, 没有这个约束。
方案 a 是 c 的退化子集（无剪枝版）, c 落地后 a 自动包含, 不单独立项。

**纠错语义的移植律**: editwordt9 纠的是「按错数字键」; 字母域的
KBN 邻键表（constants.rs:586-599, QWERTY 对称策划表）不可直接套用
（QWERTY 邻接 ≠ 九宫邻接）。开源等价 = **九宫物理邻接表**
（3×4 键盘几何: 2↔{1,3,5}, 5↔{2,4,6,8}, …, 9↔{6,8}）——纯几何常识,
非闭源原厂数据, 机制上复用 typo_retry 的 substitutions 生成器 + 罚分合并
（typo_retry.rs:65-79, 354）, 在**数字串层**做单替换变体再重走 T9 通道。
editpinyin 的字母域纠错在展开后自然生效, 无需重复实现。

## 5. 分阶段实施计划

### P1 单字九宫（口径: 2-6 键, 单/双音节域）

- 内容: ① `query` 签名加 T9 模式位（镜像 jianpin 旗标管线——CLI
  `-p` 先例 main.rs:787, wasm `jianpin_inject` 先例 lib.rs:86;
  建议枚举化 `mode: Pinyin|Jianpin|T9` 而非再加 bool）;
  ② T9 模式分支置于数字白名单门**之前**（query.rs:809 前分叉,
  T9 域内 2-9 是字母键, 不过 strip_tones）;
  ③ 签名表构建（启动期, 音节表×6 键最短匹配）+ `q_t9(inp)`:
  DFS 展开（§3-c）→ q_jianpin 消费口 → `Kind::T9`（新增枚举值,
  面板语义同 Jianpin）。
- 验收探针（P1 出面板即过, 暂不卡排序）:
  - `64` → 你/呢/泥/拟…（单音节 ni 列）
  - `7464` → expansions {pi,pin,ping,qi,qin,qing,ri,si} 的字列并集
  - `64|74` 混串 `6474` → 双音节字组合面（ni+qi 族）
  - 反例: `99`、`9999` → 空面板（纯辅音域归零律, §2.2-2）
  - 时延: 6 键内 p95 < 1ms（bench 黄金集口径, ADR-002 附录10 律）

### P2 词级/句级（口径: ≤12 键整消耗域）

- 内容: ① `t9_dat_compose`（= 数字签名版 jianpin_dat_compose,
  50,000 步预算 + cap 48）; ② `t9_sent_beam`（= 数字版 jianpin_sent_beam:
  状态 (已消费键数, 已闭词列, DAT 前缀态), 3..=12 键, 词 logp 入搜——
  channels_full.rs:80-129 同构）; ③ >12 键走窗口律
  （q_long_panel 同律截前缀, query.rs:931-953 先例）;
  ④ L4 打分/用户词/awb 过滤零改动验证（展开产物同形）。
- 验收探针:
  - `94664486` → 中国 top1; `64426` → 你好 top3; `42694264` → 好像 top3
  - 句级: `546842633842674`（jintiandetianqi, 15 键窗口）→ 今天…天气 族 top3
  - 在途: `94664` 前缀面板含 中/钟/种 字列 + zhong 前缀补全词（sepd 对位）
  - 时延: 8 键 p95 < 10ms; 12 键预算帽触发率 bench 报告（§7-R4）

### P3 九宫纠错

- 内容: ① 九宫邻接表（几何常量, constants.rs 新增 8 桶位掩码,

  - `94664486` 错击一邻键（如 9→8: `84664486`）→ 中国 回 top3
    （zhong→8hong? 需枚举验证: zhong 首键 9(wxyz)→8(tuv), z→t/u/v 域

## 7. 风险与未解问题清单
