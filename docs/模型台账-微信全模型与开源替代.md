## 二、逐件详述

### 1. nlrgptand——手机端神经语言模型（核心）

**干什么**：整条「语境增强」链的大脑。四个消费点共享统一入口 `nnlm_score`（注入即换脑）：
- M4 候选重排（L4 融合公式 `final = f6 + clamp(0.23·λ·ΔN, ±1.5)` 的 ΔN 项）
- B7 句序列重排（句组内 NNLM 序写回——宽档 cap160/8000 升默认的主战场）
- c.3 词块感知组装的束扩展引导（逐层按 NNLM 截束）
- 联想语境

**结构**（`nnlm_mobile_fp32.safetensors` 元数据实证）：2 层 pre-LN GPT，d_model=192，
4 头 × head_dim=48，ctx=128，vocab=5594（字级）。轻量件特征：GELU 用原厂 fp16
圆整常量、bos 双 oracle、前缀组批（分桶裂变+跨组合批，~8×）。

**我们的替代**：`nnlm_open_mobile_v2`——**逐位同构**（2×192×4×48/ctx128），词表
8917（比腾讯 5594 大——语料覆盖更广），LCCC 2.2B 字 40k 步自训。三格式导出。

**为什么同构自训**：① 这是能力核心，权重即行为，无「常量化」捷径；② 同构使
装载器/前向/golden 对照**零改动**（`variant: "mobile"` 元数据路由，注入即用）；
③ 训练数据用开源 LCCC（聊天语料）——与输入法场景同分布；④ 效果实证全面追平
或超越：B7 句重排 36.5/98.1（=腾讯件逐位平）、v4 语境 70.2（+1.0pp）、held-out
NLL 4.89 vs 腾讯 5.36。10 个配方全测后 v2 朴素配方终审连任。

### 2. nlrgpt2——PC 端高级版（大杯，已退役）

**干什么**：PC 端同角色大杯（3 层 d256/ctx512/vocab 5594；GELU tanh 精确常数；
附加 64 维 ±1 z 签名头——`z_flag` 门控，语义未破解）。

**我们的替代与决策**：自训 v1/v2a-d 全系测完。**退役依据**（统计实证）：
- 引擎真候选 2000 query McNemar：mobile 胜（p=0.001）
- 合成同音电池 adv +10pp（p<0.0001）——「逐位置似然 ≠ 候选间排序边际」，
  两电池各胜一摊，产品口径（引擎真候选）mobile 胜
- 咨询定案：2 层即输入法重排的正确容量，第 3 层为负资产
- 曾误判「架构固有崩塌」（引擎链式法则 bug，已修）；修复后复测结论不变
- 单句时延曾 7.8s（无批）→ 批化后 14.5×（30 变体 458→32ms）——**留作对照资产**

### 3. md.bin path_rank LR——切分路径排序器（免训）

**干什么**：拼音串有多条切分路径（`xian` = xi'an / xian / …），LR 对每条路径的
特征向量打分排序。160 个系数对应 160 维路径特征。

**为什么不训练**：逆向发现 160 系数里**只有 f14 活跃**（整音节先验：消费键数与
音节数越匹配越好），其余特征通道惰性。W14 常量（1 行代码）复刻主效应后，md.bin
曾经影响结果的两个缺口案（`xian→先`、`xianzaishi→现在是`）双案闭合（均 #1）。
重训 160 系数 = 花一轮训练复刻已覆盖的效应，边际价值≈0。

### 4. mix recall MLP——纠错候选门（免训）

**干什么**：打错拼音时引擎深召回会产生「纠错类候选」（Kind::Correct），MLP 逐个
打分决定去留（8 特征：本候选分/通道内最高分/complete 通道最高分/全池 bigram
最高/本候选 bigram/全池名次/通道内名次/纠错通道名次）。

**为什么免训**：两层依据——
- **可移植部分已移植**：51 个 float 权重 + 门逻辑逐语义移植进引擎（行为即复刻）
- **训练分布结构性不存在**：golden 13,263 个 native 候选 correct 类 = 0；我们引擎
  纠错已被 exact/fcomp 通道吸收（`buxcuo→不错#1[exact]`），q_correct 通道是永远
  轮不到的兜底。没有候选分布 → 没有采集目标 → 训练无从谈起

### 5. mdltr——候选排序 LightGBM（数据件就绪，接线待特征语义）

**干什么**：Learning-to-Rank 树模型，179 维特征 → 候选名次（lambdarank，
sum-of-leaves 推理）。

**我们的替代**：`mdltr_open`（LTR_DUMP 采集引擎真特征 × LightGBM 自训，
Apache-2.0）。**状态**：数据件与装载器就绪，但 179 维特征语义未破解 →
排序接线挂起（接线错语义=乱序，不如不接）。

### 6/7. lmcn / bgrm——n-gram 统计语言模型（同构自训）

**干什么**：lmcn 双表（unigram 35 万+bigram 40 万）供联想链 Viterbi 打分；
bgrm（766,962 条 bigram）供候选融合式提分。

**替代**：lmcn_open（LCCC 统计重建，**逐位同**——替换后评测逐位一致）、
bgrm_open（LCCC jieba bigram）。n-gram 是纯统计表，开源语料可完整等价。

### 8. wltm——英文词级 LM（角色等价重建）

**干什么**：微信英文线模型（资产在，引擎未接线——我们逆向时 PC 英文线无消费点）。

**替代**：`enlm_open_v2`——4 层 d256/ctx256/25k 词表，**词级**建模（--word-level
模式），wikitext-103 自训。接 CLI `--enlm`（P(w|BOS) 单前向重排，april/nixon
语境差异实证）。**我们接了自己没接的线**——腾讯自家 wltm 在引擎里反而未消费。

## 三、决策分类学（为什么这么做）

| 策略 | 适用件 | 判据 |
|---|---|---|
| **同构自训重替** | mobile NNLM / lmcn / bgrm / mdltr / enlm | 能力核心、行为=权重、开源语料可等价；同构保装载器/golden 零改动 |
| **效应覆盖免训** | md.bin LR | 小模型主效应单特征 → 1 行常量复刻，缺口案实证闭合 |
| **权重移植免训** | mix recall MLP | 微型门控模型 → 51 float 直内嵌即行为复刻；训练分布不存在 |
| **退役留档** | nlrgpt2 adv | 产品口径统计实证劣于现役（McNemar p=0.001）；批化留对照 |
| **角色等价重建** | wltm → enlm | 原件未接线无从对拍 → 按管线角色重建并接线 |

**总纲**：替代深度与「行为可对证性」成正比——能逐位对照的（NNLM/n-gram）同构
重训；行为可被简单机制覆盖的（LR）常量化；行为即权重的（MLP 门）直移植；
统计劣汰的（adv）退役。每一步都有产品口径实证（golden 611 逐位 / 2000 query
McNemar / v4 语境 70.2），不靠感觉。

## 四、兼容性设计（替代件怎么做到「注入即换脑」）

- **容器元数据路由**：`variant: "mobile"|"advanced"` 一个字段决定装载器分派——
  同一 CLI `--nnlm` 旗标 / wasm `init_nnlm` 接口通吃全部变体
- **三格式导出**：每款自训件带 fp32（对照）/ fp16（部署）/ int8（嵌入式）三档
- **缺件优雅降级**：全部开源件缺席时引擎自动退化为纯词频基线（golden 同律），
  不炸不静默错
- **engine-glue/app 契约**：`init(dictBytes, {nnlmBytes})` 注入即开宽档——
  替代件在 native/wasm/浏览器三端同一套接线

## 五、红线注记

腾讯原件（nnlm_mobile/advanced_fp16|fp32、lmcn 原表、bgrm、mdltr、md.bin、
mix 权重导出 md_params.json）仅本地研究对照使用，不入 git、不分发；开源部署
（open bin 线）默认产品路径零腾讯消费（`腾讯资产审计.md` 四组 A/B 实证）。
逆向行为常数（W14、MIX_RECALL 权重、融合公式）属引擎行为复刻本体，不构成
数据资产消费点（审计档「复刻行为常数豁免口径」）。
